# Generated portable tool metadata

`tools/owners/aqua/aqua.yaml` owns selected native versions and tags; its
generated `aqua-checksums.json` supplies artifact hashes. Python versions
belong to dependency groups in `tools/owners/aqua/pyproject.toml`. Files in
this directory, the root Python catalog, repository membership, and local
facade extras are compatibility outputs, not additional version owners.

After an intentional edit or Renovate update, refresh owners and check the
derived files:

```console
python3 tools/internal/aqua/refresh_owners.py
python3 tools/internal/aqua/sync_repository.py --check
python3 tools/internal/sync_readme.py --check
```

The refresh uses the Aqua checksum API for the pinned build-time bootstrap,
updates Aqua's selected artifact checksums, exports the existing Multitool
URL/hash/archive layout, derives Python versions and environment selection,
then syncs the generated tool README. The existing Bazel labels and runner
arguments remain stable. The adapter supports the migrated asset layouts and
is not a generic Aqua-to-Multitool converter.

Ordinary Python dependency metadata is generated by
`tools/internal/aqua/python_package.py`; `prepare_dependency_release.py` builds
a local wheel from the maintained owners using an explicit release version and
configurable package identity. `check_dependency_release.py` validates the
wheel binding through standard `uv` and `uvx` consumers. These maintained
tools do not read or write experiment snapshots and do not publish or register
a package.

Renovate uses the pinned Aqua preset and PEP 621 manager on the production
owners. Its single post-upgrade refresh command is allowlisted by the daily
workflow. `experiments/**` is excluded from update discovery so historical
owners and generated package snapshots do not compete with production sources.
